# MASTER SPEC — Тёплая Компания 4.0 / Alpha 6

## 1. Назначение
Мобильная корпоративная система управления строительной/монтажной компанией. Одна общая база данных, разные интерфейсы и права по ролям.

## 2. Роли
- Руководитель/Администратор — полная управленческая картина.
- Инженер — замеры, объекты, ТЗ, монтажники, план/факт, фото, расходы по объектам, график оплат.
- Менеджер — лиды, клиенты, замеры, КП, договоры; Alpha 6 содержит только каркас интерфейса.
- Монтажник — только назначенные объекты, собственные задания, фото/видео, расходы, собственная оплата, инструмент и СИЗ.

Пользователь не выбирает себе реальную роль. Роль назначает администратор. В демо доступен только предпросмотр интерфейса ролей.

## 3. Главная цепочка объекта
Лид → Замер → Запланирован → Подтверждён клиентом → ТЗ готово → Готов к монтажу → В работе → Работы завершены → Закрыт 100%.

`Закрыт 100%` возможен только когда:
- работы выполнены;
- оплаты закрыты;
- расходы внесены;
- обязательные отчёты/документы закрыты.

## 4. Главный экран руководителя
Верхние KPI:
1. Оборот.
2. Прибыль.
3. Объекты в работе.
4. Запланированные объекты.
5. Планируется поступление.

Ключевые показатели:
- Лиды.
- Замеры.
- Договоры.
- Средний чек.
- Дебиторка.
- Расходы.

Быстрый доступ:
Объекты / Монтажники / Инженеры / Менеджеры / Финансы / Аналитика / Календарь / Справочники.

Требует внимания — бесконечная вертикальная лента проблем/контроля.

## 5. Обязательное UX-правило
Каждая цифра живая. Любой KPI должен раскрываться до первичного источника: объект, платёж, расход, сотрудник, замер, лид, этап ТЗ.

## 6. Оборот
Оборот = все фактические поступления выбранного периода.

Drill-down:
Оборот → Общий оборот / Промежуточные платежи / Оплаты по закрытым объектам → объект → платёж → карточка объекта.

## 7. Прибыль
Прибыль периода = фактический оборот − все фактические расходы периода.

Отдельно внутри детализации допускается аналитика прибыли по закрытым объектам.

## 8. Объекты в работе
Только физически начатые работы. В детализации: адрес, клиент, инженер, монтажники, текущий день/этап ТЗ, план/факт, фото, расходы, оплаты.

## 9. Запланированные объекты
Очередь будущих монтажей. Разделяется на:
- Запланирован / ещё не подтверждён.
- Подтверждён клиентом.

Перед переводом в работу система проверяет полноту ТЗ.

## 10. Проверка ТЗ перед запуском
Обязательны: клиент, адрес, вид работ, инженер, монтажники, сумма каждому монтажнику, этапы, объёмы, план по дням, график оплат, даты и суммы платежей, материалы/ресурсы, комментарии.

## 11. Скользящий календарь
Объекты имеют плановое окно старта и длительность. Переносы сохраняют причину. Один монтажник не может быть назначен на два пересекающихся объекта.

## 12. Планируется поступление
Сумма будущих неоплаченных этапов действующих/подтверждённых ТЗ. Drill-down по датам → объектам → этапам ТЗ.

## 13. Дебиторка
Только просроченные платежные этапы. Drill-down: сумма → объект → этап → дата → дней просрочки → звонок клиенту.

## 14. Расходы
Верхний уровень:
- По объектам.
- Расходы компании / прочие.
- Личные.

Для объектных расходов: статья, подстатья, объект, ответственный, сумма, дата, комментарий, чек.

Рекомендуемые подстатьи: материалы, зарплата/аванс, топливо, расходники, инструмент, доставка, вывоз мусора, транспорт, прочее.

## 15. Лиды / Замеры / Договоры
Будущие вкладки Google Sheets:
- Лиды — владелец процесса SMM.
- Замеры — инженер.
- Договоры — менеджер.

Контроль свежести:
- лиды/замеры — ежедневное обновление;
- договоры — сигнал, если нет движения 7 дней.

## 16. Договоры
Для управленческого KPI: текущие объекты в работе + завершённые в выбранном периоде. Коммерческие данные договора хранятся внутри объекта, без дубля карточки.

## 17. Средний чек
Сумма договоров / количество договоров. Drill-down по направлениям: утепление, фасады, кровля, комплекс. Утепление дополнительно: пол, стены, перекрытие, кровля, комбинации, полное комплексное утепление.

## 18. Монтажники
KPI: всего монтажников, сегодня на объектах, закрыто объектов, к выдаче. Карточка монтажника: контакты/личные данные, текущий объект, дни, объекты, начислено, выплачено, к выдаче, инструмент, форма/СИЗ.

## 19. Зарплата монтажников
Начисление создаётся из ТЗ по конкретному человеку. `К выдаче = начислено − авансы − частичные − финальные выплаты`.

## 20. Инженеры
В административном приложении кнопка Инженеры раскрывает «рабочий мир» инженера: замеры, конверсия, активные/плановые объекты, ТЗ, монтажники, расходы, план/факт, фото, переносы, платежи, просрочки, отсутствие отчётов.

## 21. Менеджеры
Alpha 6 — только каркас. Полноценный CRM-контур проектируется отдельно.

## 22. Финансы
KPI: Оборот, Расходы, Общий остаток, Подотчёт.

Приход: сумма, дата, объект, этап ТЗ, получатель/подотчётное лицо, способ оплаты, комментарий.
Расход: тип, статья, подстатья, объект/монтажник при необходимости, ответственный, сумма, дата, комментарий, чек.
Передача: кто → кому, сумма, комментарий. Не расход.

## 23. Аналитика
Фильтры: период, объект, статус, вид работ, инженер, менеджер, монтажник, статья расходов/финансы.
KPI: оборот, прибыль, расходы, дебиторка, план поступлений, осталось получить, средний чек, объекты, сроки, конверсии, выручка/прибыль по направлениям, загрузка сотрудников, просрочки.

## 24. Профиль и настройки
Фото, ФИО, телефон, должность, роль read-only. Справочники редактируемы без кода. Отдельная кнопка синхронизации.

## 25. Синхронизация
Будущая схема: Android ⇄ Google Apps Script API ⇄ Google Sheets.
Требования: двусторонняя синхронизация, ID-ключи, идемпотентность финансовых операций, время последней синхронизации, очередь несинхронизированных записей.

## 26. Журнал изменений
В production обязательно хранить кто/когда изменил статус, дату, сумму, зарплату, ТЗ или календарь.
