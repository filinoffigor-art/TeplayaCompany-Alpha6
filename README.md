# Тёплая Компания 4.0 — Stage 1

Нативный Android, `ru.teplayakompaniya.tk4`, версия `6.2.0-stage1` / `602001`. minSdk 26, targetSdk 34, compileSdk 35, Java 17, Gradle 8.11.1. Рабочий Apps Script `/exec` сохранён.

Stage 1 включает обновлённые главную, навигацию, календарь, настройки, фильтры уведомлений, реальные фото профиля, проверенные снимки API по аккаунтам/периодам и явные состояния отсутствующих данных. Legacy SharedPreferences не удаляются; demo fallback не используется.

Дополнение: отрицательный подотчёт и невозмещённые собственные средства, формы возмещения, перемещений монтажников, наёмников и их рабочих дней. Новые записи **не активированы**, пока backend не поддерживает безопасные команды и не возвращает соответствующие capabilities. Существующие ТЗ доступны для просмотра: редактирование через старый API может пересоздать ID оплат.

## Сборка и проверка

GitHub Actions выполняет JUnit, Android Lint, сборку APK и офлайн-проверку на API 34 (412×915 dp). QA-артефакт содержит скриншоты, отчёты и результат проверки локальных данных после обновления. Тестовые данные находятся только в androidTest, не в приложении.

```sh
gradle testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest assembleRelease
node scripts/stage1-migration-test.cjs
```

## Подпись и установка

Старый workflow не сохранял debug.keystore. Новая сборка сравнивает сертификат с фактическим Alpha6.1. `QA-ONLY` означает, что APK нельзя считать обновлением уже установленного приложения. Не удаляйте установленную версию ради обхода несовместимой подписи.

Для совместимого APK необходим **исходный** private key. При его наличии workflow поддерживает секрет `ANDROID_DEBUG_KEYSTORE_BASE64` для стандартного прежнего debug-keystore. Новый произвольный ключ совместимость не восстановит. Тест обновления baseline с тем же CI-ключом проверяет сохранность данных, а не совместимость с реальным установленным APK.
